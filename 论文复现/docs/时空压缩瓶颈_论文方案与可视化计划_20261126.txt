时空压缩瓶颈：论文方案与可视化验证计划
日期：2026年11月26日

一、当前结论
15轮、2820次参数更新、独立750个验证GOP：
仅空间27.920dB，25dB达标669/750；完整浮点21.339dB，95/750；完整量化21.216dB，79/750。
三组已用统一入口全量复现，模型及检查点未改动。
浮点与量化只差约0.123dB，不能把本轮约6.58dB的空间/完整浮点差距都归给量化。
但空间组保留约17.45倍的特征标量且不量化。当前证据指向“时空压缩+分支+容量变化”组合，不足以指认时空注意力算子存在错误；时空解码器也在差异范围内。
15轮结果不代表各模型收敛上限。

二、最先做的隔离实验（不需要先换整套网络）
新增一组：保留相同残差时空编解码和MoE，去掉公共/个体分解，直接用浮点时空特征解码。
与现有完整浮点比较，可观察分支压缩的影响；与空间组比较，继续观察额外时空压缩的影响。
这仍非等码率实验，必须同时记录特征形状、元素数量、参数、耗时。
当前已发现图7最后GELU位置差异，另用50脚本独立测试，不能一边改激活、一边改分支和量化后再归因。

三、相关论文与可借鉴方案

1. VCT: A Video Compression Transformer（NeurIPS 2022）
https://research.google/pubs/vct-a-video-compression-transformer/
论文思路：逐帧得到表示，通过Transformer建模跨帧表示的条件分布，而非必须依赖显式运动估计。
本项目推论：空间表示质量较好时，不必默认通过更深的时空下采样来利用时间冗余。可先保持逐帧表示，再研究时间上下文。
重要限制：原方法含熵建模/实际压缩链路；当前固定3-bit模型若只加Transformer却不编码概率，不会自动获得同等码率节省。不能把VCT改名成当前复现或直接照搬其指标。
优先级：作为结构方向参考；近期先做“不分支时空模型”隔离，不立刻替换整套系统。

2. Deep Contextual Video Compression（NeurIPS 2021）
https://proceedings.neurips.cc/paper/2021/hash/96b250a90d3cf0868c83f8c965142d2a-Abstract.html
https://github.com/microsoft/DCVC/tree/main/DCVC-family/DCVC
论文思路：在特征域利用上下文进行条件编码。
本项目推论：可检验“公共特征作为条件引导个体编码/解码”，而不仅是固定F-C、压缩后再相加。
建议插入点：个体压缩前与接收端融合处；用轻量可学习融合做单变量对照。
约束：接收端条件必须来自收到的信息或可同步的解码状态；不能偷用发送端原始特征。改变融合并不自动意味着CBR或真实负载不变，必须核算。
优先级：分支隔离后，若问题主要来自分解/融合再尝试。

3. Temporal Context Mining for Learned Video Compression（预印本2021，TMM期刊版本）
https://arxiv.org/abs/2111.13850
https://github.com/microsoft/DCVC/blob/main/DCVC-family/DCVC-TCM/README.md
论文思路：传播已解码特征、学习多尺度时间上下文并注入压缩模块。
本项目推论：保留接收端可用的多尺度特征，可能比仅在8×8表示上恢复纹理更有效；但未经发送或接收端重建的编码器跳连不可使用。
成本与风险：缓存、上下文计算、参考失配与丢包误差传播。若采用跨GOP状态，还需关键状态刷新与丢包鲁棒性设计；不是零成本增强。
优先级：中后期，不在当前复现阶段直接接入整套递归架构。

4. Scale-Space Flow for End-to-End Optimized Video Compression（CVPR 2020）
https://openaccess.thecvf.com/content_CVPR_2020/html/Agustsson_Scale-Space_Flow_for_End-to-End_Optimized_Video_Compression_CVPR_2020_paper.html
论文思路：运动补偿结合尺度自由度，处理运动不确定性、遮挡等情形。
本项目推论：若错误随运动增大，可先引入轻量GOP内对齐对照；不是先假定3D Swin不能建模运动。
代价：运动特征需要学习或传输，必须计入负载、计算与延迟。该方法不是在任何场景下都让图像“更锐利”，也不等于后处理锐化。
优先级：运动分组诊断支持后再做，不能为当前静态纹理模糊直接认定它有效。

5. Soft then Hard（ICML 2021，既有调研补充）
https://proceedings.mlr.press/v139/guo21c.html
先软噪声训练，再固定编码端、真实量化微调接收侧的思想仍可作为候选。
但根据本轮浮点/3-bit只差0.123dB的证据，当前优先级低于分支/压缩隔离；不能指望它直接补回空间/完整模型全部差距。

四、等元素高分辨率候选（本项目假设，不冒称论文原方法）
此前Step37只在固定小样本测试过高分辨率窄通道路径，尚没有完整双分支多视频证据。
如后续指向低分辨率瓶颈，可比较120×8×8与30×16×16，两者每帧元素数相同。
若扩展到完整双分支，需要同时设计公共/个体形状、MoE头数兼容和恢复器，重新核算两路负载；不能只改一个中间张量就宣称预算公平。
更高空间分辨率换来更窄通道，两者都有信息损失风险。保持标量数也不保证量化误差、真实码率或计算相同。

五、后续所有训练的可视化规范

每个实验保存：
  1. 运行配置、变体、数据/源码版本、种子和预算。
  2. 每轮训练重建MSE、验证MSE/PSNR、MoE辅助损失曲线。
  3. 已完成轮次、参数更新次数、耗时、目标轮次。
  4. 固定同一验证GOP的原图/重建；跨模型必须同场景、同尺度、同显示范围。
  5. 最好/中位/最差图，明确是按哪个模型/集合挑选，不把不同场景硬当横向图像对比。
  6. last/best、history/result、逐GOP/逐视频表，必要时导出短视频观察闪烁。
  7. 对照结论应同时引用曲线、图像与负载，不能仅凭最高PSNR宣称通信性能最优。

当前已新增51只读可视化工具：
python -B tools/51_visualize_training.py
python -B tools/51_visualize_training.py --watch
默认监视Step46，生成outputs/training_visualization/step46/dashboard.html与curves.png。
--watch每60秒重新生成文件，HTML每60秒刷新；关闭监视器不影响训练。其他实验可指定--root和--output。
它不执行重建推理，也不更新模型；重建图由49或固定同场景对比52生成。未来训练的定期重建仍需要在各入口接入，不能把只读曲线监视器说成已经统一改造了所有旧训练脚本。

当前没有自动启动新的候选训练；待确认具体下一组后，按本规范准备独立入口和可视化。
